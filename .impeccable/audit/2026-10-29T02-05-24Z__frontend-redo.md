## Implementation Integrity Verdict

**Pass.** The implementation expresses one system, and it is this product's:
- tokens live once in `style.css` `@theme` and flow through five shared primitives (`ui.jsx`);
- each mode owns one fill, and the same fill reappears in its header, primary button, selected prompt count and
  step numbers, so colour carries meaning instead of decoration;
- the threshold is drawn as a line through every candidate bar and the verdicts read the backend's own
  threshold, so the most important screen is no longer a generic leaderboard (the previous critique's main lapse).

Detector, source scan: 2 warnings, both `border-accent-on-rounded` at App.jsx:219 (dialog header) and :628 (task
card header). **False positives**: these are 2px ink dividers under a coloured header band, the same weight as
every border, not a coloured accent stripe on a rounded card. Advisories: `hard-offset-shadow` (the chosen
neobrutalist direction, waive) and `codex-grid-background` (see P3). URL scans add advisories only: placeholder
contrast (P2 below), one straggler word and a flat heading scale on mobile.

## Detailed Findings by Severity

### [P1] Untyped prompt text is below contrast minimum
- **Location**: App.jsx:751 (`text-faint` on the prompt box), token `--color-faint: #9a96ae` in style.css
- **Category**: Accessibility
- **Impact**: The not-yet-typed part of the sentence is the content the user has to read and copy. At 2.77:1
  on `#fbfbfd` it fails for low-vision users, and in bright light for everyone. axe misses it because the
  visible copy is `aria-hidden` (the sr-only copy is what it checks), so this was measured directly.
- **WCAG**: 1.4.3 Contrast (Minimum), AA
- **Recommendation**: Show "typed vs untyped" without dropping below 4.5:1: untyped in `ink-2` (8.8:1 on
  white), typed in `ink` plus a mint underline or tint. Keep the coral block for wrong characters.
- **Suggested command**: /impeccable colorize

### [P1] On a phone the result is off-screen and never announced
- **Location**: App.jsx:873 onward (identify results), authenticate results; `autoFocus` on "Try another sentence"
- **Category**: Accessibility / Responsive
- **Impact**: At 390x844, after submitting, the verdict card's top is at -765 px: the user sees the bottom of the
  ranking and the next-round button, not "Best match: Andrei". Focus moves to that button, and the verdict is not
  in a live region, so screen-reader users hear only "Try another sentence". The previous critique flagged the
  same gap ("the result never scrolls into view or announces itself"); the redesign didn't close it.
- **WCAG**: 4.1.3 Status Messages, AA; 2.4.3 Focus Order
- **Recommendation**: When a verdict arrives, move focus to the verdict heading (`tabIndex={-1}`) or scroll it into
  view, and give the verdict a `role="status"` / live region. Keep Enter-to-continue by handling it at the
  verdict, not by parking focus on the bottom button.
- **Suggested command**: /impeccable harden

### [P1] Dialog doesn't contain or restore focus
- **Location**: App.jsx:204 (`Dialog`)
- **Category**: Accessibility
- **Impact**: Measured: Keep recording → Tab → Discard → Tab → page body → "Enroll" tab, all behind a modal marked
  `aria-modal="true"`. After Escape, focus lands on the "Enroll" tab, not the "Identify" tab that opened the
  dialog. Keyboard users can act on the hidden page while a destructive question is open.
- **WCAG**: 2.4.3 Focus Order, 2.1.2 (expected modal behaviour per ARIA APG dialog pattern)
- **Recommendation**: Use the native `<dialog>` element with `showModal()` (built-in focus containment, inert
  background, Escape, and focus return), or trap Tab between the two buttons and restore focus to the opener.
- **Suggested command**: /impeccable harden

### [P1] "Change name" fails contrast on the mint header
- **Location**: App.jsx:558 (`GhostButton`, `text-ink-2` on `bg-mint`)
- **Category**: Accessibility
- **Impact**: 4.39:1 at 13.5px bold, just under 4.5:1. axe flagged it in every enroll state, desktop and phone.
- **WCAG**: 1.4.3, AA
- **Recommendation**: Ghost buttons on a coloured header use `ink` (9.0:1 on mint); keep `ink-2` only on white.
- **Suggested command**: /impeccable colorize

### [P1] Keystroke timestamps include handler lag (pre-existing)
- **Location**: App.jsx:416 (`t: performance.now()` inside the React key handler)
- **Category**: Implementation Integrity / Performance
- **Impact**: The model reads hold and flight times of ~80–150 ms. Lag between the key event and the handler
  measured median 1.4 / p90 8.9 / max 13 ms at normal CPU, and 5.1 / 40.5 / 59 ms at 4x CPU throttle (a slower
  laptop, or a busy one). That jitter lands directly in HL/IL/PL/RL. The old UI on `main` measured 1.1 / 7.7 / 13
  and 4.7 / 36.4 / 54 ms, so the redesign adds ~10% at most; the cause is the capture method, not the styling.
- **Recommendation**: Record `e.timeStamp` (when the browser created the event, same clock as `performance.now()`
  in current browsers) instead of reading the clock in the handler. This changes capture, not
  `features/extract.py`, so the training/live invariant is untouched; re-check live scores against the Aalto
  thresholds afterwards since live timing gets slightly cleaner.
- **Suggested command**: /impeccable harden

### [P2] Placeholder text below contrast
- **Location**: App.jsx:659, :782 (`placeholder:text-faint`, 2.86:1 on white); also flagged by the detector
- **Category**: Accessibility
- **Impact**: "e.g. Andrei" and "Start typing… pasting is off" are hard to read; the second carries an
  instruction (pasting is disabled) that exists nowhere else on screen.
- **WCAG**: 1.4.3 (placeholder text counts)
- **Recommendation**: Placeholder in `ink-2`, or move the paste note out of the placeholder into the meta row.
- **Suggested command**: /impeccable clarify

### [P2] Small tap targets on phone
- **Location**: mode tabs (104–122 x 36 px), "Change name" (111 x 20), "Show raw event log" (126 x 20)
- **Category**: Responsive
- **Impact**: All pass WCAG 2.5.8's 24 px minimum through the spacing exception, but sit below the 44 px
  recommendation; the 20 px text buttons are the ones a thumb misses.
- **Recommendation**: Give ghost buttons a 44 px hit area with padding (visual size unchanged); tabs to 44 px
  tall below `md`.
- **Suggested command**: /impeccable adapt

### [P2] Second token copy and stray hard-coded colours
- **Location**: map.html `:root` (re-declares ink, page, mint, coral, …); App.jsx:926 `bg-[#c9c6d8]`, :189
  and :782 `#fff`
- **Category**: Theming
- **Impact**: The map's palette is a hand copy of `style.css`; a token change will drift between the two pages.
  `#c9c6d8` (below-threshold bars) has no token.
- **Recommendation**: Add `--color-below` (or reuse `faint`/`wash`) and `white` tokens; have the map page load
  the same token file (a tiny shared CSS file served to both), or at least note the copy as the second source.
- **Suggested command**: /impeccable polish

### [P2] A malformed rates response blanks the whole app (pre-existing)
- **Location**: App.jsx:513–516 (`/identify/rates` never checks `r.ok`), used at the rates tiles
- **Category**: Implementation Integrity
- **Impact**: If the backend answers that route with an error JSON body (e.g. a 500 with `{"detail": …}`),
  `identifyRates.found_percent[n]` throws during render and React unmounts everything. Observed in testing with a
  stub; real backends return this shape on failure.
- **Recommendation**: Only `setIdentifyRates` when `r.ok`; the rates are optional by design (the comment already
  says so).
- **Suggested command**: /impeccable harden

### [P3] Reduced motion freezes the busy indicator
- **Location**: style.css:98–106 (global 0.01ms kill)
- **Category**: Accessibility
- **Impact**: With reduced motion the scan rings stop; the button text ("Comparing against the gallery…") still
  signals work, so state is preserved. Acceptable, but a slow pulse or the label alone is a more deliberate
  alternative than a frozen spinner.
- **Recommendation**: Hide the rings under reduced motion rather than freezing them.
- **Suggested command**: /impeccable animate

### [P3] Grid background reads as template
- **Location**: style.css:41 (detector advisory `codex-grid-background`)
- **Category**: Implementation Integrity
- **Impact**: The faint 32 px grid is common in generated neobrutalist pages. It suits a "work surface" reading but
  adds no information. Taste call, not a defect.
- **Recommendation**: Keep, or replace with a flat mint wash; decide in a critique pass.
- **Suggested command**: /impeccable critique

## Patterns & Systemic Issues

- **One faint token used for content.** `faint` was meant for de-emphasis, but it carries two pieces of real
  content (the untyped prompt and the placeholders). Every contrast failure traces to `faint` or to `ink-2` on a
  coloured fill.
- **Results don't manage focus.** Both verdict screens rely on `autoFocus` on a bottom button; neither announces
  itself. One pattern fix (focus/announce the verdict) covers identify, authenticate and the enrolled card.

- **Visible focus everywhere**: a 2–3px ink outline on every stop in the tab order.
