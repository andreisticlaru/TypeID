First results: the 200k-step model on held-out people

Rank-1 accuracy: the correct person is the system's top pick

Accuracy vs. training steps

Mean over 10 random draws of 1,000 held-out subjects. Step 0 is the untrained model. Hover for values and spread.

Mean ± standard deviation across 10 draws, in %. Median true rank = median position of the correct person among the 1,000 enrolled (1 is best), averaged over draws.

Cumulative match curve (CMC)

How often the correct person appears within the top N candidates, for the final model and an untrained model. Mean over 10 draws.

How to read this

What is being tested

Identification (1:N). Given typing from an unknown person, rank everyone enrolled from most to least similar and see where the true person lands.

This is not verification (1:1, "is this who they claim to be?"), which is scored with EER. Published verification numbers are not comparable to Rank-N accuracy here.

How the test runs

  1. Take 1,000 subjects the model never saw in training, drawn from the 16,859 held-out subjects.
  2. Enroll each with 3 typing sessions (one typed sentence each). Their embeddings are averaged into one profile.
  3. Query with one more session per subject, a different sentence from any used for enrollment, so the model can't lean on content.
  4. Rank all 1,000 profiles by cosine similarity to each query.
  5. Repeat with 10 different random draws (seeds) and average.

Reading Rank-N

Pure chance would give N/1,000: 0.1% at Rank-1 and 2% at Rank-20. Even an untrained network beats chance, because raw timing features carry some signal. The gap between the untrained and trained rows is what training added.

What the ± means

The standard deviation across the 10 draws: how much a score moves when a different random set of 1,000 subjects and sessions is used.

The mean of the 10 draws is tighter than a single draw. Every checkpoint is scored on the same draws, so comparisons between checkpoints are cleaner than the ± suggests.

What the curve shows

Caveats

  • Each query is a single typed sentence, usually one window of at most 50 keystrokes. That is a short sample. Combining several sessions per query would score higher, so this test is deliberately strict.
  • Scores are for this protocol only: a gallery of 1,000 and 3 enrollment sessions. Larger galleries score lower.
  • The same held-out pool was used to compare checkpoints, so the best-checkpoint number is slightly optimistic.
  • Data is the Aalto copy-typing task. Freely composed text is untested.

Not yet tried

  • Hard negative mining. Random negatives are mostly easy, so many training triplets probably contribute no gradient.
  • Protocol sensitivity. More enrollment sessions or several probe sessions per query.
  • Verification EER, to compare with published verification results.
  • Margin and learning-rate tuning.

Sep 20, 2026

First full training run

The encoder was trained for the first time, and a held-out evaluation was built to measure it.

  • Trained the encoder from random weights: a 20,000-step trial first, then a full 200,000-step run (batches of 64 triplets, Adam, learning rate 1e-3), saving a checkpoint every 10,000 steps. The full run took about 1 h 57 min (21:14 to 23:11).
  • First held-out evaluation of the 20k-step model, on one draw of 1,000 unseen subjects: Rank-1 17.7% and Rank-20 70.6%, against 4.6% and 28.6% for an untrained model.
  • Sped up the triplet sampler from about 79 ms to 0.1 ms per triplet. A 150,000-item Python list was being converted to an array on every call.
  • Added the Rank-N evaluation script (eval/rank_n.py), --save-every numbered checkpoints, and checkpoints that bundle the weights with their settings. A --resume option (continue from a checkpoint, including Adam's state) was added afterwards and is not committed yet.
  • Debugged train.py with a 200-step smoke test first: wrong batch key names, missing imports, a nonexistent attribute. Training loss on the test fell from 0.228 to 0.205.

Train and evaluation people kept strictly separate

Evaluation must test people the model has never seen, so the split is by subject, not by sample.

Sep 14, 2026

Sampler finished, and a hidden data problem fixed

Finishing the sampler exposed windows that held almost no typing.

  • Finished sample_triplet and sample_batch: anchor and positive from the same person in different sessions, negative from a different person.
  • Found that some windows held only a few real keystrokes (as few as 1 of 50). The 25-keystroke minimum only checked whole sessions, so the leftover tail of a long session slipped through as a near-empty window.
  • The extractor now drops any tail window under 25 keystrokes, and the training cache was rebuilt: 3,343,148 to 2,483,167 windows, every one with at least 25 real keystrokes.
